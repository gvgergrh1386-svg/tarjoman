# راهنمای مشارکت

[English](../CONTRIBUTING.md)

پایتون ۳.۱۰+، Node ۲۰+ و Chrome لازم است. `npm ci` را اجرا و سورس را با Load unpacked بارگذاری کنید. جاوااسکریپت ساده است و Acorn فقط ابزار توسعه است. آزمون‌ها کلید سرویس نمی‌خواهند.

`background` موتور و worker؛ `content` ابزار سایت و پخش‌کننده؛ `popup` تنظیمات؛ `pages` کارگاه؛ `shared` ابزار مشترک؛ `locales` متن رابط؛ `_locales` متن Chrome؛ `bridge` پل؛ `dev` آزمون و `tools` ساخت و بررسی است.

`shared/settings-core.js`، `shared/i18n.js` و کاتالوگ‌های فارسی و انگلیسی را ویرایش و `python tools/build_i18n.py` را اجرا کنید. `shared/settings.js` تولیدی را مستقیم تغییر ندهید؛ همراه سورس است تا نصب بدون ساخت ممکن باشد.

کلیدها معنایی و پایدار باشند. متغیرهای `GXT.i18n.t(key, {namedValue})` و مجموعهٔ کلیدها در زبان‌ها یکسان باشند. دادهٔ نامطمئن را با textContent یا فراردهی نمایش دهید. قالب‌های قدیمی HTML باید ساختار تگ و صفت را حفظ کنند و متغیرهایشان در محل استفاده فراردهی شود. متن سرویس HTML مورد اعتماد نیست. اتصال زنده فقط برای برچسب رابط است، نه ویرایش کاربر یا محتوا.

برای زبان سوم کاتالوگ، فایل بومی Chrome و متن پل را اضافه کنید؛ زبان و جهت را در پیکربندی زبان و اعتبارسنجی ثبت، گزینهٔ انتخاب و آزمون را اضافه و فایل‌ها را در `tools/public-files.json` تأیید کنید. هستهٔ کش و درخواست بازنویسی نمی‌خواهد. مقصد محتوا قابلیت جداست. قلم و چینش را با فرد مسلط بررسی کنید.

```sh
npm ci
python tools/build_i18n.py --check
node tools/check_i18n.cjs
python tools/test_all.py
python tools/test_all.py --browser
python tools/build_release.py
python tools/verify_release.py
```

بررسی رشته‌ها استثناهای دقیق و دارای دلیل را می‌سنجد؛ یک فایل کامل را معاف نکنید. فهرست استخراج در `locales/inventory.json` و دسته‌بندی در [معماری](architecture.md) است. دستور مدل، شناسه، توضیح کد و دادهٔ کاربر متن رابط نیستند.

آزمون پایه زبان navigator را فارسی می‌کند تا ادعاهای قبلی حفظ شوند. نصب مستقل فارسی/انگلیسی و ارتقا با `dev/release_smoke_377.py` سنجیده می‌شود؛ `--help` را ببینید. نمایه و محتوا ساختگی‌اند و کیفیت مدل واقعی را ثابت نمی‌کنند. گزارش‌ها در `.audit` می‌مانند. اگر Chrome یافت نشد متغیر `CHROME` را به فایل اجرایی بدهید.

آزمون قدیمی و خروج ناموفق را حفظ کنید. تأخیر، لغو، جابه‌جایی زمانی و بسته‌شدن را بسنجید. نمایش نباید هویت درخواست را تغییر دهد. مدل و کیفیت دستور را صرفاً برای هزینه تغییر ندهید. فایل جدید فقط با درج در فهرست عمومی وارد بسته می‌شود؛ gitignore کافی نیست. PR باید مسئله، نتیجه و آزمون را با دادهٔ ساختگی توضیح دهد. گزارش حساس مطابق [سیاست امنیت](security.fa.md) خصوصی باشد.
